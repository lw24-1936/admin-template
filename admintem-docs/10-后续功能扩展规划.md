# 10-后续功能扩展规划

> 本文是对《02-系统设计文档》8.2 的展开：给出**建议优先级、实现路径、影响面、
> 验收要点**，便于按需排期。改动时须遵守《07-维护与文档同步约定》并复跑回归。

## P0（安全与治理，建议尽快）

### 1. 验证码与登录风控（🟡 风控已完成，验证码待做）
- 已完成（D4）：账号维度 + **IP 维度**双计数与告警日志，见《02》3.4 与《09》第 17 节；
  配置项 `admintem.auth.ip-limit-enabled`（默认关闭，生产建议开启）。
- 仍待做：图形验证码（登录/注册）。实现：`/auth/captcha` 生成（键入 Redis
  `admintem:captcha:{uuid}`，TTL 2min），登录入参携带 captchaId/captchaCode 校验；
  影响面：AuthService.login/register、LoginRequest、前端登录/注册表单、permit-urls 调整。
- 验收：验证码错 3 次刷新；同一 IP 1 分钟 > 20 次返回 429/业务码。

### 2. 操作审计入库（✅ 已完成：落库与越权留痕）
- 已实现：`sys_auth_audit_log` 表（V1.0.5）+ `@AuditLog` 注解 + `AuditLogAspect` 切面，
  覆盖登录/注册/登出/改密与用户、角色、权限共 17 个管理动作；两处 403 出口额外记录
  `ACCESS_DENIED`（越权尝试）。字段含操作人、动作、目标、结果、耗时、IP、traceId。
  设计见《02》第 13 节，验证见《06》。
- 剩余（本项后续）：
  - **审计查询页面与接口**：新增 `GET /sysAuthAuditLog/page`（按操作人/动作/时间/结果过滤）
    + 桌面端「审计日志」菜单；届时需新增菜单权限标识并同步《05》（当前只有 SQL 查询能力）；
  - **自动归档/清理**：按 `admintem.audit.retention-days` 定期清理（可选接入 `@Scheduled`，
    或由运维按《04》的清理 SQL 执行，当前选择后者以免引入定时任务依赖）。

### 3. 接入 Actuator 监控
- 实现：引入 `spring-boot-starter-actuator`，暴露 `/actuator/health,metrics,loggers`；
  /actuator 加入白名单或限定内网；配合日志与慢 SQL 形成可观测三件套。
- 验收：/actuator/health 返回 UP；metrics 可见 hikaricp 连接池。

## P1（业务增强）

### 4. 第三方登录 / SSO
- 方案 A（本系统用户表）对接微信/企业微信/钉钉换取 openid 后绑定 sys_auth_user；
- 方案 B 对接统一 OAuth2 网关；在 `AuthService` 增加 `loginByOauth(provider, code)`，
  登录成功沿用 JWT + Redis 快照机制。
- 验收：第三方回调后自动登录并下发本系统令牌；首次登录自动建档并分配 common 角色。

### 5. 页面级“组件路由”远程化
- 现状：动态路由组件由 `views` 静态打包，component 字段映射本地文件。
- 扩展：将 component 改为 URL/远程模块地址（如 `remote://base/xxx.umd.js`），前端用
  SystemJS/import-maps 或 `dynamic import(url)` 加载并注册，可实现“上传组件即上线”。
- 验收：新增远程组件后无需重新部署前端即可访问新菜单页。

### 6. 多端会话与在线管理
- 现状：单账号单令牌（白名单单 key）。
- 扩展：白名单 key 升级为 `admintem:auth:jwt:{userName}:{deviceId}`，登录时下发
  deviceId（前端 UA/指纹）；提供“在线会话”查询与强制下线接口（新增菜单+按钮权限）。
- 验收：手机/PC 同时在线互不顶号；管理员可踢指定设备。

### 7. 数据权限（行级）
- 需求：不同角色看到不同数据范围（全部/本部门/本人）。
- 影响面较大，建议单独立项：引入组织架构（sys_dept）后在查询 XML 中按
  数据权限表达式拼接过滤；先做“本人/全部”两级最小实现。
- 验收：test 角色用户列表默认仅本人创建的数据。

### 8. 改密码强度策略与账号策略
- 密码复杂度校验（长度/字符集）、首次登录强制改密、密码历史记录；
- 位置：UpdatePasswordRequest 校验 + AuthService。

## P2.5（移动端增强，基础版之后的自然延伸）

移动端当前只实现登录 + 首页 + 我的（见《02-系统设计文档》第 11 节），按优先级建议：

### 12. 移动端承载轻量管理动作
- 候选：用户列表只读查询 + 启用/停用、重置密码、角色授权查看；
- 复用同一 `permission_key`（如 `sysAuthUser:paginQuery`），按钮仍由 `v-perm` 控制；
- 验收：`test` 账号在移动端看不到无权按钮，直接调接口仍 403。

### 13. 移动端会话与安全
- 会话超时前主动续期或提前提示；生物识别/手势解锁本地加锁；
- 与《10-后续功能扩展规划》第 6 项（多端会话）一并落地后，可在移动端展示并管理在线设备。

### 14. 移动端工程化
- 打包为 H5 + 壳应用（Capacitor/uni-app 容器）以接入扫码、推送、离线缓存；
- 引入 Vant 按需导入与分包，进一步压缩首屏体积；
- 增加移动端单测与 E2E 用例（现有 `tests/e2e-mobile-login.cjs` 已作为基线）。
