生成器在实现过程中暴露了一个**解析陷阱并已修复**：初始化脚本刻意在 `INSERT ... VALUES`
的多行之间插入了中文说明注释（如"普通用户：仅工作台"），若不清除注释，
注释会被当成行首内容，导致该行解析出的角色 ID 变成 `NaN`——表现为
"某个角色的授权凭空消失"（首次生成时 `common` 角色的菜单数为 0）。
修复方式是在解析前剥离 SQL 行注释与块注释，并复算核对：`common` 恢复为 1 个菜单。

## 6. 已知限制与说明（设计内）

1. **单账号单令牌（旧版兼容）**：未传 `deviceId` 时同一账号再次登录会覆盖旧令牌（旧令牌立即 401）；
   传 `deviceId` 后按设备独立保存，多端互不覆盖（后续多设备会话实现，见《10》第 6 项）；
2. 注册用户默认仅“工作台”，如需更多页面由管理员在角色授权中开启；
3. 查询接口按菜单权限授权（进入页面即可查），更严格口径见设计文档 4.4；
4. 页面级路由为 **DB 驱动的完全动态路由**（V1.0.2 起）：新增页面 = 放组件 + 菜单登记
   component 相对路径 + 授权即可，无需改前端路由表（见设计文档 8.1）；
5. 生产环境需替换 `admintem.jwt.secret` 等配置（见部署手册）。
