### 5.3 执行与验收方式

1. **先 token 后页面**：E1 落地后再改页面，避免样值散落；
2. **每改一页即截图**：截图输出到 `admintem-docs/design-preview/`（仅图片、便于你直接查看），
   我这边无法直接看图，因此以程序化断言（几何、对比度、无溢出、组件未解析告警）为客观门槛，
   **主观观感以你的截图评审为准**；
3. **不回退硬指标**：两端构建通过、桌面 E2E 21 项、移动 E2E 41 项、回归 78 项、`npm run test` 10+6 项；
4. **不新增依赖、不替换组件库、不改接口与权限逻辑**（纯展示层改造）；
5. 完成后同步《02 设计文档》（新增"视觉语言与 token"小节）与两端 README 的界面说明。

## 6. 明确不在本轮做的（避免范围失控）

| 项 | 原因 |
| ---- | ---- |
| 多端会话（`jwt:{userName}:{deviceId}`）与在线设备管理 | 属功能扩展，见《10》第 6 项，需产品确认 |
| 数据权限（行级）、组织架构 | 需要新表与新模型，属立项级改动 |
| 引入新中间件（MQ、ES、任务调度） | 与"优化"目标不符，改变部署形态 |
| 技术栈替换（如换 ORM、换 UI 库） | 破坏既有契约与交付基线 |
