# 15 · 后端方法日志规范

目标：**每个 Controller / Service 公共方法都能从日志看到入参、返回值、耗时与异常**，
同时不把密码、令牌写进日志文件。

## 1. 覆盖范围

`ApiLogAspect` 的切点：

```java
execution(public * com.admintem.web.controller..*.*(..))
|| execution(public * com.admintem.web.service..*.*(..))
```

| 能记录 | 说明 |
| ---- | ---- |
| Controller 公共方法 | 入参、`Result` 返回值、异常、耗时 |
| Service 公共方法 | 入参、返回值、异常、耗时（含实现类） |
| 异步/线程池里的 Service | 正常记录（审计异步落库也能看到） |

| 记录不到 | 原因 / 替代 |
| ---- | ---- |
| 同类内部 `this.xxx()` 调用 | Spring AOP 代理限制；由外层方法日志覆盖，必要时拆 Bean |
| `private` / `static` 方法 | 同上，不建议为日志改可见性 |
| MyBatis Mapper | 由 `sys-sql` 独立日志记录 SQL 与参数 |
| Controller 参数绑定失败 | 方法未进入；由 `GlobalExceptionHandler` 记录参数校验/解析日志 |
| Filter / Interceptor | 由 `RequestTraceFilter` 记录请求起止 |

## 2. 日志格式

```text
方法调用开始: method=AuthController#login, args=[{"username":"admin","password":"***","rememberMe":false}]
方法调用开始: method=AuthServiceImpl#login, args=[{"username":"admin","password":"***","rememberMe":false}]
方法调用完成: method=AuthServiceImpl#login, return={"token":"***","user":{...}}, cost=547ms
方法调用较慢: method=AuthServiceImpl#login, cost=547ms, threshold=500ms
方法调用异常: method=AuthServiceImpl#login, args=[{"username":"admin","password":"***"}],
              error=BusinessException: 用户名或密码错误, cost=519ms
```

- 每条日志自带 traceId（logback `%X{traceId}`），可直接串起一次请求的 Controller → Service → SQL；
- 业务异常用 **WARN**，堆栈放 DEBUG；非预期异常用 **ERROR + 完整堆栈**；
- 慢方法（默认 ≥500ms）额外 WARN，便于发现性能问题；
- Controller 与 Service 会各打一条，属于预期（能看到分层耗时）。

## 3. 配置

```yaml
admintem:
  log:
    aspect:
      enable: true       # 总开关；false 时不打印方法入参/返回值
      max-length: 1200   # 单段 args/return 最大字符数，超出截断
      slow-ms: 500       # 慢方法阈值，0 表示关闭慢日志
```

| 配置 | 默认 | 说明 |
| ---- | ---- | ---- |
| `enable` | true | 关闭后异常仍由全局异常处理器记录 |
| `max-length` | 1200 | 防止整页列表/大字段撑爆日志；截断后附原始长度 |
| `slow-ms` | 500 | 超过阈值打 WARN，不影响业务 |

日志文件（logback 已配置滚动 + 异步）：

```text
logs/admintem-backend-info.log     # INFO/WARN/ERROR
logs/admintem-backend-error.log    # ERROR
logs/sql/admintem-sql.log          # SQL
```

## 4. 脱敏与体积控制

`LogSanitizer` 统一处理：

- **JSON 字段**：`password`、`oldPassword`、`newPassword`、`confirmPassword`、
  `token`、`accessToken`、`refreshToken`、`authorization`、`secret`、`secretKey`、
  `captcha`、`verifyCode` → `"***"`；
- **toString 降级**：`password=xxx`、`token=xxx` 等键值对也会被替换；
- **Bearer 令牌**：`Bearer eyJ...` → `Bearer ***`；
- **文件参数**：只记录文件名/大小/Content-Type，不读内容；
- **流 / Servlet 对象 / byte[]**：只记录类型或长度；
- **超长**：按 `max-length` 截断并标注原长度，避免大响应拖慢日志。

> 手机号、邮箱等业务字段仍会记录（排查需要）；如涉及合规要求，
> 可把对应字段加入 `SENSITIVE_JSON` 正则或在 DTO 上做日志脱敏。

## 5. 使用与排查

```bash
# 看某个 traceId 的完整链路
grep 'a1b2c3d4' logs/admintem-backend-info.log

# 看所有异常
grep '方法调用异常' logs/admintem-backend-info.log

# 看慢方法
grep '方法调用较慢' logs/admintem-backend-info.log

# 只看登录链路
grep 'AuthServiceImpl#login' logs/admintem-backend-info.log
```

## 6. 实测样例

错误密码登录（密码已脱敏）：

```text
方法调用开始: method=AuthController#login, args=[{"username":"admin","password":"***","rememberMe":false}]
方法调用异常: method=AuthServiceImpl#login, args=[{"username":"admin","password":"***","rememberMe":false}],
              error=BusinessException: 用户名或密码错误, cost=519ms
```

成功登录（令牌已脱敏、返回值截断）：

```text
方法调用完成: method=AuthServiceImpl#login,
              return={"token":"***","user":{"userId":1,"userName":"admin",...}}, cost=547ms
```

| 验证项 | 结果 |
| ---- | ---- |
| 入参 | ✅ Controller + Service 均打印，密码/令牌为 `***` |
| 出参/return | ✅ 打印 JSON（超长截断并标注长度） |
| 异常 | ✅ WARN/ERROR + 方法名 + 参数 + 耗时；非预期异常带堆栈 |
| 慢方法 | ✅ ≥500ms 额外 WARN |
| 脱敏扫描 | ✅ 日志中未出现明文密码/令牌 |
| 单测 | ✅ `LogSanitizerTest` 覆盖 JSON、toString、Bearer、文件、截断 |
| 回归 | ✅ 后端全量测试通过；桌面 E2E / a11y 通过 |

## 7. 注意事项

1. **日志量**：默认 INFO 会记录每次调用的入参与返回，生产高并发下建议
   把 `max-length` 调小（如 600）或仅在排障时开启；关闭开关后仍有异常日志。
2. **不要**在业务代码里再打印完整 DTO；避免与切面重复。
3. 新增敏感字段时同步更新 `LogSanitizer.SENSITIVE_JSON` 并补单测。
4. 切面只读参数，不修改业务对象；`MultipartFile` 不会被消费。
5. 大文件上传不要走 Controller 返回值打印；当前只记文件元信息。
