# 04-部署与操作手册

## 1. 环境要求

| 组件 | 版本 | 说明 |
| ---- | ---- | ---- |
| JDK | 17（本机 C:\dev\Java\jdk17） | Spring Boot 3.5 最低要求 |
| Maven | 3.9.x | 使用 JDK17 作为 JAVA_HOME |
| Node.js | ≥ 22（本机 v24.x） | Vite 8 要求 |
| MySQL | 8.x（本机可连远程 100.71.112.119:3306） | 库 admintem_new |
| Redis | 6/7（远程 100.71.112.119:6379） | database 0 |

连接信息默认在 `admintem-backend/src/main/resources/application-dev.yml`，
与旧项目一致（root / 密码见该文件注释，勿外传）。

## 2. 后端部署

### 2.1 启动（开发）

```powershell
cd admintem-backend
$env:JAVA_HOME = 'C:\dev\Java\jdk17'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
mvn spring-boot:run
```

或打包后运行：

```powershell
mvn -DskipTests package
java -jar target/admintem-backend.jar
```

默认端口 **8090**。验证：
- 健康/接口文档：http://localhost:8090/swagger-ui/index.html
- API 兼容别名：`/api/v1/**` 会被后端剥离前缀后复用旧路由，并返回 `X-API-Version: v1`；
  旧客户端继续使用 `/auth/login` 等原路径即可。
- 登录冒烟：见第 5 节

> **优雅停机**：服务已启用 `server.shutdown=graceful` 与
> `spring.lifecycle.timeout-per-shutdown-phase=30s`。停止时先拒绝新请求，
> 再等待在途请求（登录、审计写入等）完成，最多 30 秒；超过上限强制结束。
> 发布时请用信号/`Ctrl+C` 停止，不要直接 `kill -9`。

### 2.1.1 数据库初始化与变更（重要：初始化脚本会清库）

**日常变更**用增量脚本（`db/changelog/V1.0.x__*.sql`，幂等可重放）：

```powershell
mysql -h 100.71.112.119 -P 3306 -u root -p --default-character-set=utf8mb4 admintem_new `
      -e "source db/changelog/V1.0.6__add_active_unique_indexes.sql"
```

**一键重置到演示基线**用 `db/init/00_admintem_full_init.sql`。注意它**会 DROP 并重建全部表**
（含审计表），因此脚本内置了安全闸门，必须显式确认：

```sql
-- 方式一：交互式（推荐）
mysql -h<host> -P3306 -uroot -p --default-character-set=utf8mb4 admintem_new
mysql> SET @admintem_confirm_reset = 1;
mysql> source db/init/00_admintem_full_init.sql

-- 方式二：脚本调用
mysql ... -e "SET @admintem_confirm_reset = 1; source db/init/00_admintem_full_init.sql"
```

未设置 `@admintem_confirm_reset` 时脚本会以 `SIGNAL` 中止，**不会删除任何表**
（这是对一次"拿初始化脚本校验 DDL 语法导致审计表被清空"事故的修复，见《09》第 18 节）。

> 在**共享库**上校验建表语法时，请复制脚本并把其中的 `USE \`admintem_new\`` 改成临时库名，
> 绝不要在目标库上直接执行初始化脚本。

### 2.1.2 Flyway 迁移（dev/test 自动执行）

`V*.sql` 的**唯一出处**是 `admintem-docs/db/changelog/`；构建时由 Maven 复制到
`classpath:db/migration`（`filtering=false`），因此不存在"文档一份、代码一份"的复制漂移。

| 环境 | 行为 |
| ---- | ---- |
| dev / test | `spring.flyway.enabled=true`：启动时自动执行未应用过的 `V*.sql` |
| pre / pro | 默认关闭：由运维显式执行脚本（避免"应用一启动就改生产结构"） |

首次接入采用**基线模式**（项目已有库）：库里没有 `flyway_schema_history` 时，
Flyway 先记录一条基线（version=0），再按版本号执行增量脚本。
实测（临时库）：基线 + `V1.0.1…V1.0.6` 共 7 条记录，`success` 全为 1，
数据仍是 2 用户 / 18 权限。

**新增一次数据库变更的步骤**：

1. 在 `db/changelog/` 新增 `V1.0.7__xxx.sql`（尽量幂等：`IF NOT EXISTS` / 守卫查询）；
2. 同步更新 `db/init/00_admintem_full_init.sql`（保证"一键初始化"与迁移后的结构一致）；
3. 在《03》登记变更说明；
4. 启动 dev 应用 → Flyway 自动应用 → 查 `flyway_schema_history` 确认 `success=1`。

> 安全设置：`clean-disabled=true`（禁止 Flyway 清库）、
> `placeholder-replacement=false`（脚本里的 `@` / `$` 字面量不被替换）。

### 2.4 容器化部署（Dockerfile）

构建上下文必须是**仓库根**（Dockerfile 通过 `../admintem-docs/db/changelog` 引用迁移脚本）：

```bash
docker build -f admintem-backend/Dockerfile -t admintem-backend:1.0.0 .
docker run -d --name admintem-backend -p 8090:8090 \
  --env-file admintem-backend/.env \
  admintem-backend:1.0.0
```

要点：多阶段构建（Maven 构建 → JRE 运行，镜像显著变小）；以非 root 用户运行；
时区固定 `Asia/Shanghai`；`HEALTHCHECK` 打 `/actuator/health`；
口令通过 `--env-file` 注入（`ADMINTEM_DB_PASSWORD` / `ADMINTEM_REDIS_PASSWORD`），不要写进镜像。

### 2.2 环境切换（Maven Profile，沿用原项目机制）

| 环境 | 启动命令 | 端口 | 前端模式 |
| ---- | ---- | ---- | ---- |
| dev（默认） | mvn spring-boot:run | 8090 | development |
| test | mvn -P test spring-boot:run | 8091 | npm run dev（.env.test 构建：npm run build:test） |
| pre | mvn -P pre spring-boot:run | 8092 | npm run build:pre |
| pro | mvn -P pro spring-boot:run | 8093 | npm run build:pro |

原理：pom.xml 定义 4 个 profile 注入 `env-flag`，配合 resources 过滤将
`application.yml` 的 `@env-flag@` 替换为实际值，激活对应 `application-{env}.yml`。

>
> **探活接口**（已加入免登录白名单，其余 actuator 端点仍需登录且未暴露）：
>
> ```bash

> # {"status":"UP","groups":["liveness","readiness"]}
> ```
>

> K8s liveness/readiness 的探针。详细组件信息刻意关闭（`show-details: never`），
> 避免对外泄露中间件拓扑。
>
> **安全指标**（Prometheus，需携带管理员令牌采集）：
> `admintem_security_requests_total{result="unauthorized|forbidden",layer="filter|method"}`、
> `admintem_login_total{result="success|failure"}`。建议为 401/403 与登录失败配置突增告警；
> 指标只保留结果/层级标签，不含账号、IP、令牌。

**开启 IP 维度风控后的应急操作**（例如误封了自己或需要立即解封某来源）：

```bash

redis-cli -h <host> -a <pwd> --scan --pattern 'admintem:auth:*ip*'

```

## 3. 前端部署

```powershell
cd admintem-vue
npm install
npm run dev          # 开发：http://localhost:5175
```

生产构建（产物在 dist/，可交给 Nginx 托管）：

```powershell
npm run build
```

后端地址配置：`src/.env.development` 中 `VITE_API_BASE_URL=http://localhost:8090`；
生产可留空并交由 Nginx 同源反代（推荐），或指向实际网关地址。

### Nginx 反代示例（前后端同域）

```nginx
server {
    listen 80;
    root /path/to/admintem-vue/dist;
    location / { try_files $uri $uri/ /index.html; }
    location ~ ^/(auth|sysAuthUser|sysAuthRole|sysAuthPermission) {
        proxy_pass http://127.0.0.1:8090;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 3.1 移动端部署（admintem-mobile，基础版）

```powershell
cd admintem-mobile
npm install
npm run dev          # 开发：http://localhost:5174（手机同网段可用日志中的 Network 地址访问）
npm run build        # 生产构建，产物在 dist/
```

- 后端地址配置：`.env.development` 的 `VITE_API_BASE_URL=http://localhost:8090`；
  生产 `.env.production` 默认留空（同源，由 Nginx 反代），也可指向实际网关地址；
- 路由为 **hash 模式**（`http://host/#/home`），静态托管无需 `try_files` 回退配置，
  Nginx 只需把 `dist` 作为静态目录并反代 `/auth`、`/sysAuthUser` 等接口前缀；
- 手机真机联调：dev server 监听 `0.0.0.0`，确保手机与电脑同网段，
  并把后端 CORS 放行该来源（后端 `admintem.security.cors` 配置项）；
- 移动端与桌面端共用同一后端、同一 `admintem_token` 约定，令牌互不影响（各自独立持有）。

## 6.5 日志与慢 SQL 查询

日志目录：`admintem-backend/logs/`（可用 `-DLOG_HOME` 覆盖），存储设计参考原项目 logback：

| 文件 | 内容 |
| ---- | ---- |
| logs/admintem-backend-info.log | 全量 INFO+（history/ 下 .gz 归档，保留 30 天） |
| logs/admintem-backend-error.log | 仅 ERROR |
| logs/admintem-backend-json.log | 结构化 JSON（含 MDC/traceId、service 字段，供 Loki/ELK 采集；history/ 下 .gz 归档） |
| logs/sql/admintem-sql.log | 全量带参 SQL（仅 dev/test/pre 开启；**敏感字段已脱敏**） |
| logs/sql/admintem-slow.log | 慢 SQL（默认 >2000ms；支持按 Mapper 分级阈值，配置 admintem.sql.slow-ms / slow-ms-by-mapper） |

每条日志行包含 `[traceId]`，可配合响应头 `X-Trace-Id` 在接口日志与 SQL 日志之间串联排查；
配置项：`admintem.sql.log-enable`（生产 false）、`admintem.sql.slow-ms`、`admintem.sql.mask-enable`（脱敏，默认开）、
`admintem.log.aspect.enable`（接口切面）、`admintem.log.trace-enable`（traceId 过滤器，默认开）。

**Prometheus 告警规则**：`deploy/prometheus/admintem-alerts.yml` 已提供 401/403/登录失败突增、
后端不可达、5xx 突增规则；在 Prometheus `rule_files` 引用即可，接入 Alertmanager 后按
`severity=warning|critical` 路由。指标不含账号/IP/令牌，告警文案不要拼接这些值。

**脱敏口径**（`SqlLogInnerInterceptor`）：参数名含 `password/pwd/secret/token` → `***`；
含 `phone/mobile/tel` → `139****5678`；含 `email/mail` → `z***@example.com`；
含 `idcard/cardno` → `110101********1234`；**其余字段名按值特征兜底**（形如手机号/邮箱/证件号的值一律脱敏）。
账号、昵称、菜单名等非敏感字段保持原样，便于排查；确需查看原值时可临时 `mask-enable: false`。

## 6.6 操作审计查询与清理

审计记录存在数据库表 `sys_auth_audit_log`（设计见《02》第 13 节），可用 SQL 直接检索：

```sql
-- 最近发生的管理动作（含失败与越权尝试）
SELECT created_time, operator, action_name, target_name, result, error_code, client_ip, trace_id
FROM sys_auth_audit_log ORDER BY id DESC LIMIT 50;

-- 某人的全部操作
SELECT created_time, action_name, target_name, result, error_msg
FROM sys_auth_audit_log WHERE operator = 'admin' AND created_time >= NOW() - INTERVAL 7 DAY
ORDER BY id DESC;

-- 越权尝试（安全关注点）
SELECT created_time, operator, request_uri, client_ip FROM sys_auth_audit_log
WHERE action = 'ACCESS_DENIED' ORDER BY id DESC LIMIT 50;

-- 由 traceId 反查该请求的审计记录（再配合日志文件即可还原整条链路）
SELECT * FROM sys_auth_audit_log WHERE trace_id = '<X-Trace-Id 响应头里的值>';
```

| 配置项 | 默认 | 说明 |
| ---- | ---- | ---- |
| `admintem.audit.enable` | true | 审计总开关；关闭后不落库（业务行为不变） |
| `admintem.audit.log-denied` | true | 是否记录 403 越权尝试；被扫描器刷量时可先关它降噪 |
| `admintem.audit.max-text-length` | 200 | 失败原因入库截断长度 |
| `admintem.audit.retention-days` | 180 | 保留天数（**仅作为下方清理 SQL 的默认值，程序不自动删除**） |

**清理（按保留期手工执行）**：审计数据属合规留痕，删除应由运维显式操作，
程序刻意不做自动清理，避免"悄悄丢失审计证据"：

```sql
-- 先看将被删除的范围与条数
```

## 7. 常见问题

| 现象 | 处理 |
| ---- | ---- |
| 登录返回 501 | 账号或密码错误；连续失败 5 次返回 502 锁定 |
| 接口返回 401 | 令牌过期/被吊销（登出当前设备、改密、重置、禁用、被管理员按设备踢下线）；重新登录 |
| 接口返回 403 | 该账号无对应 permission_key；到“角色管理→分配权限”勾选后再试 |
| 按钮不显示 | 说明当前用户权限集合缺少该按钮 key（与 403 同因，属预期前端隐藏） |
| 中文乱码 | 确认请求头 Content-Type 带 charset=utf-8；服务端已强制 UTF-8 |
| 连接数据库/Redis 失败 | 确认处于可访问 100.71.112.119 的网络（如内网/VPN），账号见 application-dev.yml |
