# 01-需求与范围

## 1. 背景

旧项目 `demo/RandomSelectionSystem`（Spring Boot 2.4.2 + JDK8）与
`demo/RandomSelectionSystem-vue`（Vue 2 + Element UI）中，已具备基于
`sys_auth_*` 五张表的 RBAC 雏形（登录、菜单权限），但存在如下问题：

- 技术栈过旧：Spring Boot 2.x / Java 8 / Vue 2；
- 注册仅为前端假注册（无后端接口）；
- 权限只到“菜单/页面”，**不能控制页面内的按钮**；
- 注销未真正使令牌失效（旧代码中 invalidateJWT 为 TODO）；
- 日志与注释不完整。

## 2. 目标

在**保持数据库与 Redis 一致**的前提下，用新栈重构权限系统：

- 后端：Spring Boot 3.5 + JDK 17 + Spring Security 6 + MyBatis-Plus + Redis；
- 前端：Vue 3（Vite 官方脚手架 create-vue）+ Element Plus + Pinia + Vue Router；
- 功能：登录、注册、用户管理、角色管理、权限管理（菜单 + 按钮），**其余旧业务不做**；
- 权限模型：**菜单权限（type=0）控制页面可见，按钮权限（type=1）控制操作可用**，
  前后端统一以 `permission_key` 为准；
- 全量中文注释 + 分层日志；
- 交付完整设计与操作文档，并约定后续修改必须同步文档。

## 3. 范围边界

### 3.1 本次实现（范围内）

| 模块 | 功能 |
| ---- | ---- |
| 认证 | 登录（记住我）、登出（服务端令牌即时失效）、自助注册（默认“普通用户”角色） |
| 会话 | 当前用户信息（含角色/菜单/权限标识集合） |
| 个人 | 修改个人资料、修改本人密码（改密后强制重新登录） |
| 用户管理 | 分页查询、新增、编辑、逻辑删除、重置密码、分配角色 |
| 角色管理 | 查询全部、分页查询、新增、编辑、删除、分配权限（菜单+按钮树勾选） |
| 权限管理 | 菜单/按钮树维护：新增子级、编辑、删除（级联清理） |
| 权限控制 | 路由守卫按菜单 key；`v-perm` 指令按按钮 key 隐藏按钮；后端 `@PreAuthorize` 兜底 |
| 操作审计 | 登录/注册/登出/改密与用户、角色、权限的管理动作落库（`sys_auth_audit_log`）；按钮级权限不足被拒绝的尝试也留痕（`ACCESS_DENIED`），可按人/动作/时间/traceId 检索 |
| 移动端（基础版） | 独立移动端工程 `admintem-mobile`：登录后底部标签栏「首页 / 我的」，复用同一后端接口与 `permission_key`，管理入口按权限渲染 |
| 其它 | Swagger 接口文档、接口调用日志 AOP、登录防暴力破解、内置数据保护规则 |

### 3.2 明确不做（范围外）

- 随机抽取业务（`sz_*` 表及其页面）；
- 验证码 / 短信 / 邮件激活、OAuth、多租户；
- 大屏等历史页面。

## 4. 数据一致性要求

- MySQL 库 `admintem_new` 与 Redis（database 0）沿用旧项目连接与账号；
- 不重构任何存量表；新增按钮权限、普通用户角色等一律通过
  `db/changelog/` 下的**增量、幂等 SQL** 落地并归档（当前 V1.0.1）；
- 每次发布前运行 `tests/api-regression-test.ps1`（78 项断言）确保不回归。

## 5. 验收标准

1. admin 登录可管理全部；test 登录可打开“用户管理”页但所有新增/编辑/删除等按钮**不展示**，
   直接调接口返回 403；
2. 新注册用户仅有“工作台”菜单，无系统管理入口；
3. 角色授权弹窗以“菜单+按钮”树勾选，保存后该角色用户重新登录即可看到/隐藏对应按钮；
4. 删除/重置密码/登出/改密后原令牌立即失效（HTTP 401）；
5. 测试全通过且不污染数据库基线（自动清理临时数据）。
